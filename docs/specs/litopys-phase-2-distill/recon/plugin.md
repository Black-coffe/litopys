## Key types / contracts

### Q1 - hooks.json / raw-journal.sh / session-start.sh
- Exact wiring (`hooks/hooks.json:2-5`): `UserPromptSubmit` -> `raw-journal.sh prompt` (timeout 10); `Stop` -> `raw-journal.sh stop` (timeout 10); `SessionEnd` -> `raw-journal.sh end` (**no** `timeout` key at all - relies on SessionEnd's own ~1.5s budget); `SessionStart` -> `session-start.sh` (timeout 10). Confirmed by `tests/hooks.test.sh:58-61` (`has("timeout")` is `false` for SessionEnd only).
- C1 root resolution, identical shape in both hook scripts (`raw-journal.sh:42-50`, `session-start.sh:25-33`): `CLAUDE_PROJECT_DIR` (if a dir) -> payload's `.cwd` (if a dir) -> `git rev-parse --show-toplevel` -> `$PWD`. This differs from `bin/litopys`'s `project_root()` (`bin/litopys:36-48`: env -> git -> pwd, **no** cwd-from-payload step) - three independent implementations, no shared library.
- session_id handling (`raw-journal.sh:36-39`): read via `field session_id`, then sanitized `tr -c 'A-Za-z0-9._-' '_'`; empty after sanitization -> `exit 0` (no journal). This id becomes the filename `<root>/.litopys/raw/<sid>.md` (line 52).
- Journal open (`ensure_journal()`, `raw-journal.sh:60-80`): no-op if the file already exists (idempotent open); else `mkdir -p .litopys/raw`, writes `.litopys/.gitignore` (`*`) if absent, resolves branch via `git -C "$cwd" symbolic-ref --short HEAD` falling back to `rev-parse --abbrev-ref HEAD` then `-`, then writes the YAML frontmatter block (`litopys: raw`, `version: 1`, `session_id`, `started`, `cwd`, `branch`).
- `## closed` write (`journal_end()`, `raw-journal.sh:55-58`): **only if `$file` already exists** (`[ -f "$file" ] || return 0` - a session that never journalled anything gets no closed marker and no file at all); appends exactly one block `\n## closed · <ts> · <reason>\n` via a single `>>`. `tests/hooks.test.sh:122-123` asserts exactly one `>>` inside `journal_end()`'s body by grep on the function source - a distill feature must not add a second write to that function without updating this assertion.
- What happens on a resumed session after `## closed`: **nothing prevents it.** `prompt`/`stop` call `append_block` -> `ensure_journal` which is a no-op once the file exists, then unconditionally appends a new `## user`/`## assistant` block *after* the existing `## closed` line. There is no re-open marker, no truncation, no new frontmatter. No test exercises resume-after-close (`tests/hooks.test.sh` never re-opens session `s1` after its `end` call at line 111-121).
- SessionStart banner line 5 (`session-start.sh:59`): `"[litopys] recall: /litopys:recall <question>"` - static text, no count. Lines 2-4 (chronicle count `:56`, last entry `:57`, raw-journal count `:58`) are the only count-bearing lines. **Where a "N journals awaiting distillation" count or a background-consolidation trigger would plug in:** line 4 already computes `raws="$(count_md "$root/.litopys/raw")"` (`session-start.sh:46`). Phase 2 would either (a) repurpose this count once distillation exists (raws not yet folded into `docs/chronicle/`), or (b) add a 6th `[litopys]` line - but C9's contract text (`hooks/session-start.sh:7-9`) is explicit that the banner stays "exactly five `[litopys]` lines" as a phase-1 constraint deliberately deferring "ask the model to do anything" to phase 2 - widening to 6 lines or changing the meaning of line 4 is a phase-2 decision to make explicitly.
- PreCompact: **confirmed absent.** `hooks/hooks.json:1-6` lists only `UserPromptSubmit`, `Stop`, `SessionEnd`, `SessionStart` - no `PreCompact` key, no reference in `hooks/*.sh`. Phase 2 has no scaffold for a PreCompact-triggered distillation; it would be a new key in `hooks.json` plus a new script/mode.

### Q2 - bin/litopys
- Dispatcher (`bin/litopys:297-305`): `SUB="${1:-help}"`, `shift`, then a `case` over `append|bench|--version|-v|version|help|--help|-h|*`. A `distill` subcommand slots in as one more `case` arm calling a new `cmd_distill "$@"`.
- `project_root()` (`:36-48`): env `CLAUDE_PROJECT_DIR` -> git toplevel -> `$PWD`. Directly reusable by `cmd_distill`.
- `cmd_append`'s C3 line (`:99-100`): `prefix="- $ts · $kind · $ref · "`; `line="$prefix$note"`. The redact call (`:87-89`): `if [ -n "$note" ] && [ -f "$root/scripts/redact.sh" ]; then note="$(printf '%s\n' "$note" | bash "$root/scripts/redact.sh" 2>/dev/null || printf '%s' "$note")"; fi`. **Exact fallback when `scripts/redact.sh` is absent**: the `[ -f ... ]` guard is false, the block is skipped, `note` passes through untouched (confirmed by `tests/append.test.sh:81-87`, project B). A separate `|| printf '%s' "$note"` covers the script-exists-but-fails case.
- `--note` collapse (`:90-91`): `note="$(printf '%s' "$note" | tr '\n\r\t' '   ')"` - runs *after* redaction, always. `--ref` is **never** collapsed or redacted - it flows straight from the `--ref` arg into `prefix`.
- `cmd_bench`'s `BENCH_USAGE_JQ` (`:126-142`): sums `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` (+ camelCase `modelUsage` equivalents) into `tokens_in`, preferring top-level `usage` when its sum is nonzero, else `modelUsage` summed across all models, else whichever object exists, else `null`. `is_error` handling (`:241-243`): `failed=1` if `rc -ne 0` **OR** `.is_error == true` - both write a row (`:278-289`), only the failure branch adds an `error` key. Non-JSON stdout: `jq -r '.result // ""'` and the usage jq both fail silently (`2>/dev/null || true`), so `res` becomes empty and `meta` empty -> `ti/to/cost` default to `"null"` (`:237`) - a non-JSON `claude` response is scored as a miss with null usage, not a crash and not an error row.
- A "skip journals whose first `## user` line starts with `/litopys:recall`" rule would **not** live in `bench` - `bench` only reads `docs/chronicle/golden-questions.md` and writes `.litopys/baseline.jsonl`; it never touches `.litopys/raw/*.md`. That exclusion belongs in whatever walks `.litopys/raw/`.
- Where `distill` slots in and what it can reuse: a new `cmd_distill()` alongside `cmd_append`/`cmd_bench` (between line 110 and 147, or after `cmd_bench` at line 295), added as a `case` arm at line 300-301. Reusable helpers: `project_root()` (`:36-48`), `trim()` (`:112-117`), the `.litopys/.gitignore` self-ignore pattern already duplicated in `cmd_bench` (`:207`) and `raw-journal.sh:64`, and the `VERSION`/`usage()` scaffolding (`:16,19-33`).

## Gotchas
- Three independent, textually-divergent copies of C1 root resolution (`bin/litopys` env->git->pwd vs. both hook scripts' env->payload-cwd->git->pwd) - a hook-invoked distill must copy the hooks' 4-step version, not `bin/litopys`'s 3-step one.
- `journal_end()`'s "closed" write only happens if the journal already exists (`raw-journal.sh:56`) - a session with zero prompts leaves **no raw journal file at all**; a distillation pass walking `.litopys/raw/*.md` never sees empty sessions.
- Resumed sessions append silently past `## closed` with no re-open marker - a distill parser must handle multiple `## closed` blocks or content following one.
- `tests/hooks.test.sh:122-123` greps the literal source of `journal_end()` for exactly one `>>` - a second write inside that function fails this assertion until updated.
- The SessionStart banner is contractually exactly 5 lines (`hooks/session-start.sh:7-9`, `tests/hooks.test.sh:152`) - adding a distillation-count line or trigger is an explicit contract change.
- No shared test-helper library across the three suites - a fourth (`distill.test.sh`) duplicates `bad/expect/refute/eq` unless `tests/lib.sh` is extracted first.

## Answer
The map slice is accurate on every point re-checked - no drift. hooks.json wires exactly `UserPromptSubmit`/`Stop`/`SessionEnd`(no timeout)/`SessionStart`; `## closed` is written once, only into a journal that already exists, and does not prevent or mark a later resume; PreCompact is absent; the banner's line 4 (raw-journal count) is the natural anchor for a phase-2 "N journals awaiting distillation" number, but growing/repurposing the banner changes its "exactly five lines" contract. A `distill` subcommand slots into `bin/litopys` as one more `case` arm reusing `project_root()`/`trim()`/the `.litopys/.gitignore` pattern; it must not be built inside `cmd_bench`. `--ref` is never redacted; the redact-absent fallback is a plain skip. Both recall search-order copies must be edited together to add a distilled-records stage. Tests have no shared helper library; a distill test follows `hooks.test.sh`'s stdin-payload pattern for hook-driven distillation, or `append.test.sh`'s CLI pattern for a `bin/litopys distill` subcommand. `plugin.json` has no explicit hooks/agents list.
