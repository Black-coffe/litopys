# Brief: litopys-privacy-guard

**Date:** 2026-09-28 · **Tier:** 2 · **Deliverable:** changed code (+ release 0.3.0)
**Governed by:** ADR-004 (`.litopys/` self-ignoring scratch dir - its invariant "no plugin code writes to a host's .gitignore" is what this spec revisits), ADR-005, ADR-007 (distill commits on the current branch)

## Request (verbatim)

Owner, 2026-09-28 (voice dictation; two words were dropped by the dictation, marked by the bare " ." - read as ".gitignore" and "GitHub", confirmed in the grill):
> Просмотреть данное решение, плагин, модуль, скилл. Он же у нас публичный на GitHub. Самое главное в плане безопасности — всё, что он генерирует в тех проектах, в которых он установлен, должно автоматически попадать в . Он должен это контролировать, об этом говорить, напоминать и в каждой сессии перепроверять. Вот в плане безопасности. И какие-то микродетальки, улучшения, если будешь замечать по ходу, тоже сделай. И давай минорную версию апдейта закатим на . И в описании на GitHub сделаем, да, чётенько.

## Answers

Grill 2026-09-28, owner answered each question (all four on the recommended option).

1. **Что прятать** - Всё + выключатель для команд: в .gitignore уходят .litopys/ и docs/chronicle/, distill перестаёт коммитить, записи остаются локально; для командного репо можно явно включить LITOPYS_TRACK_CHRONICLE=1, и старый коммит вернётся.
2. **Уже в git** - Громко предупреждать + готовая команда: каждую сессию «в git N файлов litopys» и команда git rm -r --cached; сам индекс не трогает.
3. **Напоминание** - Тебе и модели, каждый раз: каждую сессию одна строка на экран, громко - когда что-то дописал или нашёл в git; модель получает то же плюс запрет на git add -f этих путей.
4. **Требования** - Верно, собирай сразу: план записать и сразу собрать в этой сессии, после зелёного ревью самому выкатить v0.3.0 и обновить описание (straight-through opt-in).

## Asks

1. Всё, что litopys генерирует в проекте (.litopys/ и docs/chronicle/), само попадает в его .gitignore; для хроники есть явный выключатель LITOPYS_TRACK_CHRONICLE=1.
2. Каждую сессию плагин это перепроверяет, дописывает недостающее и говорит об этом тебе и модели; файлы, уже лежащие в git, — громкое предупреждение с готовой командой.
3. Микродефекты из разведки исправлены.
4. Минорный релиз 0.3.0 выкачен на GitHub: push main, тег v0.3.0, Release с заметками.
5. Описание репо на GitHub (About, топики) и README чистые и точные.
